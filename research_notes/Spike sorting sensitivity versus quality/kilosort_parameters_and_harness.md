# Kilosort sensitivity parameters, how their defaults were chosen, and the user's tuning harness

Scope: KS4 as checked out in this repo (fork of MouseLand/Kilosort at `v4.1.7-69-gde3467c`, branch `ks4-tuning`) and KS2.5 as run by the lab's neuropixels pipeline (`C:/code/github/neuropixels/ExternalToolboxes/KilosortToolbox/Versions/kilosort_v2.5`, presets in `+SpikeSort/+Kilosort/+Config/kilosort_config_v2_5.m`). Local code paths are cited as `file:///` links; they were read on 2026-11-04. Several publisher pages (PMC, nature.com, figshare PDF, Europe PMC full text) were blocked by CAPTCHA, login redirects or server errors, so the KS4 paper was read in its bioRxiv version (Pachitariu, Sridhar, Pennington & Stringer, "Solving the spike sorting problem with Kilosort", 2023), which became the 2024 Nature Methods paper. ## Q1. What each sensitivity-type parameter actually controls in the code (KS4 and KS2.5), and whether later stages can make up for lowering it

### Takeaway
In both versions the main "Th" thresholds act on a matched-filter score in whitened-noise units. They are not raw voltage thresholds. KS4's `Th_learned` is applied to relu(projection)²/‖template‖², i.e. variance explained with a free amplitude and no amplitude prior, so in effect the score is fitted amplitude × template norm. KS2.5's `Th` is applied to a score that includes an amplitude prior weighted by `lam`, so it also measures how well a spike's amplitude fits its unit. KS2.5 then has a per-unit, refractoriness-driven cut (`set_cutoff`) that raises each unit's threshold from Th(2) back towards Th(1) when the unit is contaminated. Stock KS4 has nothing like it: spikes admitted by a low `Th_learned` stay in the output. They can only be regrouped by the final reclustering and merge, and removed only if they fall within 0.25 ms of a spike of the same unit.

### Cited findings

**KS4 pipeline order (this repo).** Spike detection with universal templates (`Th_universal`) → first clustering (`mode='spikes'`) → first template merge (`merge_correlation_threshold_1`, 'mu' mode with no correlograms) → template matching with the learned templates (`Th_learned`, `max_peels`) → second clustering (`mode='template'`, merge tree with a refractoriness veto) → final CCG merge (`merge_correlation_threshold_2`, `ccg_threshold`, `acg_threshold`) → same-unit duplicate removal (`duplicate_spike_ms`) — [run_kilosort.py](file:///C:/code/github/Kilosort/kilosort/run_kilosort.py) (lines ~761–970), [template_matching.py](file:///C:/code/github/Kilosort/kilosort/template_matching.py) (`postprocess_templates`, lines 144–156).

**KS4 parameters**
- **`Th_universal` (default 9).** Described as "Spike detection threshold for universal templates. Th(1) in previous versions of Kilosort" — [parameters.py](file:///C:/code/github/Kilosort/kilosort/parameters.py) L61–69. In code, the whitened data are convolved with the temporal universal templates `wTEMP` and projected onto spatial weight profiles normalised to unit L2 norm (`weigh = weigh / (weigh**2).sum(1)**.5`). A detection is a local maximum over 2·nt0min+1 samples and over nearby template positions (`iC2`) with `As > Th_universal`. The threshold is therefore on a unit-norm matched-filter output, in units of whitened-noise SD — [spikedetect.py](file:///C:/code/github/Kilosort/kilosort/spikedetect.py) L140–190, L256–258. These spikes are used only to learn templates; the final spikes come from the learned-template pass. The KS4 paper says the universal-template detection step "leaves about 50% of spikes undetected, which it considers acceptable for template learning" (WebFetch paraphrase) — [bioRxiv KS4](https://www.biorxiv.org/content/10.1101/2023.01.07.523036v1.full).
- **`Th_learned` (default 8).** Described as "Spike detection threshold for learned templates. Th(2) in previous versions" — [parameters.py](file:///C:/code/github/Kilosort/kilosort/parameters.py) L71–79. In `run_matching`, `Cf = relu(B)**2 / nm` with `nm = ‖U‖²`, and peaks are accepted when `Cmax > Th**2`. The recorded amplitude is `B/nm`, and `th_amps = sqrt(Cmax)`, i.e. relu(B)/‖U‖. The score is the reduction in squared residual (variance explained) from subtracting the best-scaled template, in whitened units. The amplitude is free and has no prior: `lam = 20` is assigned but never used — [template_matching.py](file:///C:/code/github/Kilosort/kilosort/template_matching.py) L204–295. The paper describes matching as scored by "variance explained, computed as the squared dot product of the unit-norm template with the data" — [bioRxiv KS4](https://www.biorxiv.org/content/10.1101/2023.01.07.523036v1.full). The user's own audit concludes "The score is amplitude, not goodness of fit… There is no misfit term and no amplitude prior… The paper's fixed-norm cost… is not what the code does" — [placement_audit.md](file:///C:/code/github/Kilosort/tuning/exploratory/autocurate/placement_audit.md) §2.1.
- **`max_peels` (default 100).** The number of matching-pursuit iterations per batch: "More iterations may detect more overlapping spikes" — [parameters.py](file:///C:/code/github/Kilosort/kilosort/parameters.py) L312–320. Each peel subtracts the accepted spikes and recomputes Cf only near them — [template_matching.py](file:///C:/code/github/Kilosort/kilosort/template_matching.py) L245–293.
- **`Th_single_ch` (default 6).** "For single channel threshold crossings to compute universal templates. In units of whitened data standard deviations" — [parameters.py](file:///C:/code/github/Kilosort/kilosort/parameters.py) L366–374. It is used only in `extract_snippets` to build `wPCA`/`wTEMP`, not to detect the spikes that are sorted — [spikedetect.py](file:///C:/code/github/Kilosort/kilosort/spikedetect.py) L34–61, L225.
- **`acg_threshold` (default 0.2) and `ccg_threshold` (default 0.25).** In `CCG.check_CCG`: `is_refractory = R12 < acg_threshold and Q12 < .2` and `cross_refractory = R12 < ccg_threshold and Q12 < .05`. R12 is the minimum, over windows of ±1…±10 ms, of the central CCG rate divided by the baseline (shoulder) rate. Q12 is a Poisson-type probability of the dip. The 0.2 and 0.05 limits on Q12 are hard-coded — [CCG.py](file:///C:/code/github/Kilosort/kilosort/CCG.py) L39–95. A code comment says "The default `acg_threshold=0.2` is different from the value of 0.1 used for the Kilosort4 paper. We felt this better reflects common practice for determining 'good' units" — [CCG.py](file:///C:/code/github/Kilosort/kilosort/CCG.py) L83–86. Both thresholds act in the final merge: only clusters that pass the ACG test (`is_ref`) seed merges (`if mode=='ccg' and is_ref[kk]==0: continue`), and a candidate pair with template correlation ≥ `merge_correlation_threshold_2` merges only if it is cross-refractory under `ccg_threshold` — [template_matching.py](file:///C:/code/github/Kilosort/kilosort/template_matching.py) L355–430. `acg_threshold` also sets the 'good' label after sorting — [run_kilosort.py](file:///C:/code/github/Kilosort/kilosort/run_kilosort.py) L1163–1167.
- **The merge tree inside clustering uses its own hard-coded limits**, not the settings: `is_refractory = R12<.1 and (Q12<.2 or sparse)`, `cross_refractory = R12<.25 and (Q12<.05 or sparse)`, with `sparse = Q00 < .25` — [swarmsplitter.py](file:///C:/code/github/Kilosort/kilosort/swarmsplitter.py) L53–77. The tree decides each node in this order: graph connectivity < 0.2 → keep apart; cross-refractory → merge; otherwise merge unless the bimodality score ≥ `merge_bimodality_threshold` (default 0.6, previously hard-coded) — [swarmsplitter.py](file:///C:/code/github/Kilosort/kilosort/swarmsplitter.py) L98–160; [parameters.py](file:///C:/code/github/Kilosort/kilosort/parameters.py) L508–518.
- **Upstream bug that disabled the refractoriness veto in v4.1.5–4.1.7.** The guard `len(st2 == 0)` is always truthy, so `check_CCG` returned (False, False) on every real input. Splits were then "decided purely by modularity and bimodality". The fork fixed this in commit 549ec32 ("Fixes #1042"), and the harness's KS4 base includes the fix — local `git show 549ec32`; [evaluation_spec.md](file:///C:/code/github/Kilosort/tuning/evaluation_spec.md) §2.
- **Hard-coded companion criteria can override the user's settings.** In MouseLand/Kilosort issue #685, raising `ccg_threshold` (0.25 → 0.5) changed nothing. The maintainer (jacobpennington) explained that "`ccg_threshold` is checked alongside a hard-coded threshold… increasing the value (i.e. making it less restrictive) may not have any effect. You should see some differences if you decrease it". The variable names in his quote are swapped relative to the current code — [GitHub #685](https://github.com/MouseLand/Kilosort/issues/685).
- **`merge_correlation_threshold_1` / `_2`** (fork settings; stock hard-codes 0.9 and 0.5). The first merge joins templates with correlation above the threshold and norms within 20%, with "no correlogram test at this step, so most candidate pairs merge". The final merge requires a refractory CCG — [parameters.py](file:///C:/code/github/Kilosort/kilosort/parameters.py) L520–543.
- **`cluster_downsampling` (default 20) / `max_cluster_subset` (25000)** set how many landmark spikes the graph clustering uses. Version history: before 4.1.0 the behaviour equalled `max_cluster_subset=None, cluster_downsampling=20`; 4.1.0–4.1.2 defaulted to `25000, 1` — [parameters.py](file:///C:/code/github/Kilosort/kilosort/parameters.py) L410–442. **`cluster_resolution`** (fork setting) "None keeps the original penalty… too weak to change most assignments" — [parameters.py](file:///C:/code/github/Kilosort/kilosort/parameters.py) L483–494.
- **`duplicate_spike_ms` (default 0.25 ms = 7 samples at 30 kHz)** removes later spikes of the *same* cluster within dt and does nothing across clusters — [postprocessing.py](file:///C:/code/github/Kilosort/kilosort/postprocessing.py) L10–30; [run_kilosort.py](file:///C:/code/github/Kilosort/kilosort/run_kilosort.py) L521–558. The docs advise raising it if "good-looking neurons" have large peaks near 0 ms, but not above 0.5 ms, because the ACG/CCG refractory estimates ignore the central bin — [KS4 docs, parameters](https://kilosort.readthedocs.io/en/latest/_sources/parameters.rst.txt).

**KS2.5 parameters (lab copy)**
- **`Th = [Th(1) Th(2)]`.** Stock config comment: "threshold on projections (like in Kilosort1, can be different for last pass like [10 4])", stock default `[10 4]` — [StandardConfig_MOVEME.m](file:///C:/code/github/neuropixels/ExternalToolboxes/KilosortToolbox/Versions/kilosort_v2.5/configFiles/StandardConfig_MOVEME.m). Th(1) is used while templates are learned (`learnTemplates.m` Params(3), and `setup_detector(rez, ops.Th(1))`). Th(2) is used in the final extraction (`trackAndSort.m`: `Params(3) = ops.Th(end); % usually the threshold is much lower on the last pass`) — [learnTemplates.m](file:///C:/code/github/neuropixels/ExternalToolboxes/KilosortToolbox/Versions/kilosort_v2.5/mainLoop/learnTemplates.m) L66–117; [trackAndSort.m](file:///C:/code/github/neuropixels/ExternalToolboxes/KilosortToolbox/Versions/kilosort_v2.5/mainLoop/trackAndSort.m) L70–81. The lab presets are "standard" `[10, 6]` and "standard_low" `[9, 4]` ("May work better than 'standard' for noisier recordings") — [kilosort_config_v2_5.m](file:///C:/code/github/neuropixels/+SpikeSort/+Kilosort/+Config/kilosort_config_v2_5.m).
- **`lam` (10): amplitude prior inside the matching score.** In `mexMPnu8.cu`: `a = 1+lam; b = max(0, data) + lam*mu; Cf = b*b/a - lam*mu*mu`, and a spike is accepted if `err0 > Th*Th`. This is the best reduction in squared residual when the amplitude is penalised for deviating from the template's mean amplitude `mu`. With lam = 0 it reduces to KS4's score — [mexMPnu8.cu](file:///C:/code/github/neuropixels/ExternalToolboxes/KilosortToolbox/Versions/kilosort_v2.5/CUDA/mexMPnu8.cu) L291–316, L395–412. Config comment: "how important is the amplitude penalty (like in Kilosort1, 0 means not used, 10 is average, 50 is a lot)" — [StandardConfig_MOVEME.m](file:///C:/code/github/neuropixels/ExternalToolboxes/KilosortToolbox/Versions/kilosort_v2.5/configFiles/StandardConfig_MOVEME.m). The 2016 Kilosort paper motivates the prior by spikes varying "in relative rather than absolute amplitude", with λ and ε weighting reconstruction error against the prior — [Pachitariu et al. 2016 bioRxiv](https://www.biorxiv.org/content/10.1101/061481v1.full).
- **`set_cutoff`: per-unit threshold recovery between Th(1) and Th(2).** For each unit it starts at `Th = ops.Th(1)` and lowers the threshold in 0.5 steps while the unit stays refractory (`fcontamination = 0.1`; it stops if `Q > 0.1 || R > .05`), with Th(2) as the floor — [set_cutoff.m](file:///C:/code/github/neuropixels/ExternalToolboxes/KilosortToolbox/Versions/kilosort_v2.5/postProcess/set_cutoff.m) L30–110. Lowering Th(2) therefore admits low-score spikes only into units that stay clean. The harness spec describes it the same way: "`set_cutoff`… lowers each unit's cut-off on the template-fit score from Th(1) towards Th(2) while the unit stays clean" — [evaluation_spec.md](file:///C:/code/github/Kilosort/tuning/evaluation_spec.md) §14.
- **`AUCsplit` (0.9).** In `splitAllClusters`, a two-Gaussian mixture is fitted along an iteratively refined pursuit direction. A split is made only if `nremove > .05 && min(plow,phigh) > ccsplit && min(sizes) > 300 && sum(ccg.K) >= 500`, where plow and phigh are the mean posterior confidences of the two sides. The code comments call ccsplit "one of the main parameters users can change" — [splitAllClusters.m](file:///C:/code/github/neuropixels/ExternalToolboxes/KilosortToolbox/Versions/kilosort_v2.5/postProcess/splitAllClusters.m) L17, L150–230. Config comment: "splitting a cluster at the end requires at least this much isolation for each sub-cluster (max = 1)".
- **`minFR`** (stock 1/50 Hz; lab KS2.5 0.05 Hz). During learning, a template whose running spike count falls below `m0 = minFR·NT/fs` is dropped ("the minimum firing rate that all templates must maintain, or be dropped") — [learnTemplates.m](file:///C:/code/github/neuropixels/ExternalToolboxes/KilosortToolbox/Versions/kilosort_v2.5/mainLoop/learnTemplates.m) L114–135; [kilosort_config_v2_5.m](file:///C:/code/github/neuropixels/+SpikeSort/+Kilosort/+Config/kilosort_config_v2_5.m).
- **`minfr_goodchannels` (0.1 Hz) and `spkTh` (−6).** Channels are kept if their rate of negative crossings of `spkTh` standard deviations (per-channel standardised, not whitened) is ≥ 0.1 Hz — [get_good_channels.m](file:///C:/code/github/neuropixels/ExternalToolboxes/KilosortToolbox/Versions/kilosort_v2.5/preProcess/get_good_channels.m) L40–67. `trackAndSort.m` overwrites `ops.spkTh = -6; % why am I overwriting this here?` — [trackAndSort.m](file:///C:/code/github/neuropixels/ExternalToolboxes/KilosortToolbox/Versions/kilosort_v2.5/mainLoop/trackAndSort.m) L50.
- **`ThPre` (8)**: "threshold crossings for pre-clustering (in PCA projection space)", used in `extractPCbatch2.m` — [StandardConfig_MOVEME.m](file:///C:/code/github/neuropixels/ExternalToolboxes/KilosortToolbox/Versions/kilosort_v2.5/configFiles/StandardConfig_MOVEME.m); [extractPCbatch2.m](file:///C:/code/github/neuropixels/ExternalToolboxes/KilosortToolbox/Versions/kilosort_v2.5/preProcess/extractPCbatch2.m) L32.

**Empirical compensation and interaction, from the user's own runs**
- In KS4, lowering `Th_universal` from 9 to 7 "was the biggest lever… more cells get a template", and it saturates (6 ≈ 7). `Th_learned` 7 "mostly adds low-amplitude spikes to existing cells" (+25 bits/s alone, +27 on top of `Th_universal` 7). 6 gives the same as 7, while 9 loses 64. `max_peels` 200 gains only +2 although the peel limit "binds in 89% of batches" — [round3_results.md](file:///C:/code/github/Kilosort/tuning/round3_results.md).
- A set_cutoff-like cut on KS4 "acts as a between-unit amplitude filter": units with median score < 9 lose 64–67% of their spikes, and "on near-threshold units this largely undoes H8's lower `Th_learned`". Per S, the refractory logic "adds nothing over a plain score floor". Post-cut contamination is optimistic by about 2× in-sample. Hybrid truth supports w ≈ 2 rather than 4 — [placement_audit.md](file:///C:/code/github/Kilosort/tuning/exploratory/autocurate/placement_audit.md) §2. The audit's short answer: "Don't move the deletion earlier. Move the refractory evidence earlier… most of KS4's contamination is a *grouping* error made in the final reclustering."

### Inferences
- `Th_universal` and `Th_learned` act at different stages and on different things. `Th_universal` changes *which units exist*, because it only feeds template learning; a low value adds candidate clusters, which later merges can absorb. `Th_learned` changes *how many spikes each existing unit gets*. No later stage removes the low-score spikes it admits, so in KS4 lowering `Th_learned` cannot be made up for downstream. Only an added cut (set_cutoff-like) or the harness's own cleaning can do that. In KS2.5, a low Th(2) is partly made up for by `set_cutoff`'s per-unit refractory test and by the `lam` amplitude prior.
- Because KS4's score is roughly fitted amplitude × ‖U‖ in whitened SDs, `Th_learned` = 8 is an SNR-like cut. Spikes just above it are mostly small-amplitude events of large-norm templates and full events of small templates. KS2.5 cut-off values therefore do not carry over numerically to KS4, as the user's audit also concludes.
- `acg_threshold` and `ccg_threshold` are not detection-sensitivity knobs. They gate merges (and labels). Because the Q12 limits are hard-coded, loosening either setting barely matters, while tightening it does; issue #685 shows the same thing.

- The upstream issue #1042 text itself was not fetched; the description comes from the fork's commit message.

## Q2. How the Kilosort authors and others chose or justified default values, and what their ground-truth or hybrid evaluations showed

### Takeaway
I found no published derivation of the default thresholds (KS4 9/8; KS2 [10 4]; acg 0.2/ccg 0.25). The official guidance is heuristic: lower each threshold "by one or two at a time" if units or spikes seem to be missing. The KS4 benchmarks scored sorters by the number of ground-truth units with score 1 − FP − FN > 0.8. Competitors' thresholds were swept to maximise that count. Kilosort 1–3 were run at [9, 8] rather than their own defaults, which shows the authors themselves ran older versions at thresholds different from their shipped defaults. Other groups run quite different values: the IBL sorter uses Th [6, 3] and the lab pipeline [10, 6] or [9, 4].

### Cited findings
- **KS4 docs.** For "Too few spikes, or units that disappear and reappear in Phy: decrease `Th_learned`. Too few units overall: reduce `Th_universal`. Lower each threshold by one or two at a time." There is no discussion of the false-positive cost — [KS4 docs, parameters](https://kilosort.readthedocs.io/en/latest/_sources/parameters.rst.txt).
- **KS4 README** (via search summary): the main parameters "can affect the results in a different way for your data", so values from older versions may not transfer — [WebSearch summary of MouseLand/Kilosort README / issues](https://www.github.com/MouseLand/Kilosort/issues/675).
- **KS4 paper benchmarks (bioRxiv).** FP = share of sorted spikes without a match (±0.1 ms), FN = share of missed ground-truth spikes. Score = 1 − FP − FN against the best of the 20 closest units. A unit is "correctly identified" if its score is "higher than 0.8". For KS1, 2, 2.5 and 3, "we set the detection thresholds to [9, 8] instead of their defaults". IronClust, MountainSort4 and SpyKING CIRCUS were swept over detection threshold, using "the detection threshold which maximized the number of correctly identified units on the medium drift simulation" (SpyKING CIRCUS 4.5; for MountainSort4 and IronClust the default was best). "All other parameters were set to their default values" — [bioRxiv KS4](https://www.biorxiv.org/content/10.1101/2023.01.07.523036v1.full).
- **KS4 paper results.** Kilosort 2, 2.5, 3 and 4 "outperformed all other algorithms in all cases". KS4 found about 80–90% of units against about 50% for IronClust. KS4 beat KS2.5 and KS3 most strongly on step drift. KS4's dependence on amplitude was "minimal", and for some other algorithms performance could not be improved by lowering detection thresholds. The paper uses refractory criteria R12 < 0.1 and Q12 < 0.2 (ACG) and R12 < 0.25 and Q12 < 0.05 (CCG), and calls units with contamination > 0.1 multi-units — [bioRxiv KS4](https://www.biorxiv.org/content/10.1101/2023.01.07.523036v1.full). (KS4 code says the 0.2 ACG default departs from the paper's 0.1 — [CCG.py](file:///C:/code/github/Kilosort/kilosort/CCG.py).)
- **The KS4 benchmark is simulation-based, not hybrid.** The paper criticises hybrid data because it "depend[s] on finding the neurons in the first place" — [bioRxiv KS4](https://www.biorxiv.org/content/10.1101/2023.01.07.523036v1.full).
- **Kilosort 2016 (bioRxiv).** The hybrid ground truth moved SVD-denoised spikes of curated KlustaKwik clusters to nearby sites; 16 instantiations. Units scoring > 0.9 before merging: Kilosort 53% vs KlustaKwik 35%; after greedy ground-truth merges, 69% vs 60%. Both sorters over-split (2–4× more clusters than neurons). Kilosort's advantage came mainly from fewer misses, attributed to resolving overlapping spikes. The detection threshold is annealed during learning, and "operator curation is still required". No sweep or rationale is given for parameter values — [Pachitariu et al. 2016 bioRxiv](https://www.biorxiv.org/content/10.1101/061481v1.full).
- **IBL's sorter (ibl-sorter / pykilosort, a KS2.5 port).** Current defaults: `Th = [6, 3]` (with the KS2 comment text), `ThPre 8`, `spkTh −6`, `genericSpkTh 8.0` ("threshold for crossings with generic templates"), `lam 10`, `AUCsplit 0.9`, `minFR 1/50`, `minfr_goodchannels 0` — [ibl-sorter params.py](https://raw.githubusercontent.com/int-brain-lab/ibl-sorter/main/iblsorter/params.py). The IBL white paper documents "several modifications that enable more scalable and robust processing" (v3 2022-05-07; v4 2024-10-14) — [figshare IBL white paper](https://figshare.com/articles/online_resource/Spike_sorting_pipeline_for_the_International_Brain_Laboratory/19705522/3).
- **Lab pipeline (Gardner et al. 2022 settings).** KS2.5 "standard" uses `Th [10, 6]`, `minFR 0.05`, `triageMergeThresh 0.975` (previously hard-coded 0.9), `checkCcgShape`, and repeated curation. "original" is Marius' settings (`Th [10, 6]`, `minFR 1/50`); "original_hq_lothresh" and "standard_low" use `[9, 4]` — [kilosort_config_v2_5.m](file:///C:/code/github/neuropixels/+SpikeSort/+Kilosort/+Config/kilosort_config_v2_5.m). KS2.1 configs in the same toolbox use `[10 4]`, and the eMouse drift simulation config uses `[6 2]` — [config_eMouse_drift_KS2.m](file:///C:/code/github/neuropixels/ExternalToolboxes/KilosortToolbox/Versions/kilosort_v2.5/eMouse_drift/config_eMouse_drift_KS2.m).
- **Lower thresholds and double counting (GitHub).** A thread on double-counted spikes reports that the lower the threshold, the higher the chance that a residual is counted as a different spike, and that newer versions double-count less (from a search-result summary; the thread itself was not opened) — [MouseLand/Kilosort #29](https://github.com/MouseLand/Kilosort/issues/29). Issue #675 (missed fast-spiking units): the maintainer suggests `templates_from_data=False` and says the units may be too noisy to be identified — [GitHub #675](https://www.github.com/MouseLand/Kilosort/issues/675).
- **Independent hybrid comparison (AIND pipeline paper, eLife).** Hybrid units come from IBL NP1 and NP Ultra templates injected at about 15 Hz Poisson, 50–200 µV, following DREDge motion; 1800 (NP1) and 3000 (NP2) ground-truth units. Accuracy = TP/(TP+FN+FP), match at accuracy ≥ 0.2. KS4 beat KS2.5 on accuracy and recall, with 3652 vs 3046 matched units. Differences were largest for SNR < 10. KS4 had slightly higher refractory contamination (effect size 0.013). No sorter parameter sweeps are reported — [Buccino et al., eLife 110170](https://elifesciences.org/articles/110170). Note: the fetched summary said KS4 showed "a slight loss of precision" but listed a positive precision effect size (0.272 NP1, 0.232 NP2), so the direction of the precision difference needs checking against the paper.

### Inferences
- The KS4 authors' implicit objective is a yield above a quality bar: count the units with 1 − FP − FN > 0.8. FP and FN count equally, and spikes count only through the per-unit threshold. Running KS1–3 at [9, 8], and choosing other sorters' thresholds by that yield on one simulation, suggests the defaults were tuned by eye or by this count on simulations, not derived. I found no statement of a deliberate FP/FN cost ratio.
- Practitioners' choices cover a wide range, from IBL [6, 3] through the lab's [9, 4]/[10, 6] to stock [10 4]. They have one structural thing in common: a lower final-pass threshold than learning-pass threshold, which matches the user's finding that the learning-side threshold mostly decides which units exist.

### Gaps
- The Steinmetz et al. 2021 Science (Neuropixels 2.0; PMC8244810) KS2.5 validation numbers could not be retrieved: the Europe PMC full-text endpoint returned HTTP 500 and the abstract has no sorting metrics.
- The IBL white paper PDF (figshare) could not be downloaded, so IBL's stated rationale for [6, 3], its deduplication and its quality-metric bars (e.g. amplitude and refractory cut-offs) are not confirmed here.
- Allen Institute `ecephys_spike_sorting` KS2 parameter choices and their justification were not retrieved.
- No maintainer statement found that explains how 9/8 (KS4) or [10 4] (KS2) were picked.

## Q3. Published systematic Kilosort parameter sweeps

### Takeaway
I found no peer-reviewed systematic sweep of Kilosort's own sensitivity thresholds against ground truth. Published benchmarks (the KS4 paper, SpikeForest, the AIND eLife paper) run Kilosort at fixed settings. Only competitors' thresholds were swept in the KS4 paper, and the AIND paper's only sweep is over compression. The user's harness, with about 124+ scored KS4 sorts across four rounds, is itself a more systematic sweep than anything found in print.

### Cited findings
- The KS4 paper swept detection thresholds only for IronClust, MountainSort4 and SpyKING CIRCUS; Kilosort versions were run at [9, 8] — [bioRxiv KS4](https://www.biorxiv.org/content/10.1101/2023.01.07.523036v1.full).
- AIND/eLife: "No sorter parameter sweeps are reported"; the only sweep is lossy compression (WavPack BPS 3, 2.5, 2.25), which "is not a sorter-parameter sweep" — [eLife 110170](https://elifesciences.org/articles/110170).
- SpikeForest: 650 recordings and about 35,000 ground-truth units. Accuracy is averaged over ground-truth units with SNR above an adjustable cut-off (shown at 8), with sorters at fixed parameters (search-result summary) — [SpikeForest, eLife 55167](https://elifesciences.org/articles/55167/figures).
- The KS4 docs provide a benchmark tutorial for reproducing the KS4 simulations with the score ≥ 0.8 rule, which can serve as a base for one's own sweep — [Reproducing Kilosort4 benchmarks](https://kilosort.readthedocs.io/en/latest/tutorials/benchmark.html).
- User's harness sweep (round 3, with the R4 merge settings): `Th_universal` 7/8, `Th_learned` 6/7/9, `max_peels` 200, `nblocks` 5, `nearest_chans` 14/20 and `n_pcs` 9, each run on 3 seeds; then the combination C1 and the extension E1 (`Th_universal` 6) — [round3_results.md](file:///C:/code/github/Kilosort/tuning/round3_results.md). Round 1 covered `ccg_threshold` 0.10/0.15 (+42/+25 bits/s single runs), `acg_threshold` 0.1 (+8.9), bimodality and resolution — [round1_results.md](file:///C:/code/github/Kilosort/tuning/round1_results.md).

### Inferences
- The published literature cannot tell the user where the sensitivity optimum lies for a given analysis. Benchmarks are designed to compare sorters, not to calibrate their thresholds, and simulation results ("minimal dependence on amplitude") may not hold for real hippocampal/MEC Neuropixels 3A data.

### Gaps
- SpikeInterface-based sweeps (e.g. MEArec-driven threshold sweeps in Buccino/Einevoll papers) and IBL's internal parameter-choice reports were not found in the time available; absence here is not evidence that none exist.
- SpikeForest's parameter-optimisation subsection (if any) was not read in full.

## Q4. What the user's harness measures, how it currently trades units and spikes against quality, and where a principled sensitivity objective could plug in

### Takeaway
The harness's objective is S. For every eligible unit it computes the cross-validated, null-corrected Poisson log-likelihood gain (bits/s) from a heading tuning curve fitted against a frozen internal-direction reference θ_ref, and sums these over units after its own duplicate and artefact cleaning. The trade-off between yield and purity is handled only indirectly. Contamination and missed spikes lower S through information loss, splits are close to free, and guards (eligible units, hybrid recovery, untuned units) and selection checks (stricter duplicate cleaning, reproducibility) guard against particular failure modes. No term explicitly penalises false-positive spikes in cells whose tuning they do not distort. The exploratory folder already contains the pieces of explicit FP/FN objectives: refractory contamination (Σ N(1−ĉ)), tradeoff curves of correctly assigned against misassigned spikes, matched random-deletion controls and hybrid agreement.

### Cited findings
- **Primary score.** `S_i = (1/T_test) Σ_c [n_ic log2(λ_i(θ_ref,c)/λ̄_i) − (λ_i − λ̄_i) d_c/ln2]`, fitted on one 10-min segment and tested on the other, both ways. Each unit's null (θ_ref rotated by k/7, k = 1…6) is subtracted, so untuned units score about 0 and S does not reward dropping them. S = Σ_i S_i — [evaluation_spec.md](file:///C:/code/github/Kilosort/tuning/evaluation_spec.md) §5.2–5.3. Improvement rule: mean ΔS ≥ δ = 28.6 bits/s (2σ over 5 default seeds), mean ΔS_track ≥ 13.6, all guards pass, ≥ 3 seeds — §5.4, §9.1.
- **Cleaning before scoring.** Multi-unit artefact events (≥ 17 units spanning ≥ 1 mm in 0.2 ms) are removed and masked. Pairwise duplicates are detected from the lag histogram (conditional binomial test, excess ≥ 3% of the smaller unit) and the coincident spikes removed. Eligibility requires ≥ 100 spikes per segment and the Bombcell-style waveform screen. KS4's good/mua labels are deliberately unused "because settings under search (`acg_threshold`, `ccg_threshold`) change them" — [evaluation_spec.md](file:///C:/code/github/Kilosort/tuning/evaluation_spec.md) §3, §6.
- **Guards.** Eligible units ≥ 0.8× default; hybrid recovery (median agreement ≥ default − τ_hyb, units with agreement ≥ 0.8 ≥ default − τ, no HD pair merged; agreement = matched/(n_true + n_sorted − matched), ±0.4 ms); untuned units (S_i below default's 25th percentile) ≥ 0.9× default; raw mask unchanged — §7.1–7.3. Selection checks: re-scoring with duplicate excess ≥ 1%, and a resolution stopping rule (choose the point where the most units reproduce across seeds, since S "plateaus rather than peaks" past the real cells) — §9.2.
- **How S responds to errors** (perturbation audit at 5% rates): merges of differently tuned units −63.6 bits/s; dropped units −55.1; contamination −55.7; thinning −51.6; splits −0.0; duplicates +51.8 before cleaning, −1.7 after — [evaluation_spec.md](file:///C:/code/github/Kilosort/tuning/evaluation_spec.md) §8.6. Known blind spots: merges of similarly tuned cells cost little, and S rewards heading information — §12.
- **The current trade-off in practice.** The winner H8 (`Th_universal` 7, `Th_learned` 7, bimodality 0, γ 2.0, final merge 0.95, downsampling 10) gains ΔS +392.9 with about 1695 eligible units against default's 772. About 1004 units reproduce across seeds against about 660 for default. Each added unit contributes about 0.21 bits/s (16% of a typical default unit) — [round4_results.md](file:///C:/code/github/Kilosort/tuning/round4_results.md); [README.md](file:///C:/code/github/Kilosort/tuning/README.md). Against the lab's KS2.5, H8 is +423.6 over "standard" and +339.1 over "standard_low". standard_low (Th [9 4]) gains about 8–9% over standard by outputting about 15% more spikes, which shows lower thresholds help S in KS2.5 too — [ks25_comparison.md](file:///C:/code/github/Kilosort/tuning/ks25_comparison.md). Decoding separates the sorters far less: direction saturates at 100 ms, and at equal unit counts "H8's units again decode worse" — [ks25_comparison.md](file:///C:/code/github/Kilosort/tuning/ks25_comparison.md).
- **Objectives considered and rejected.** Population decoding (von Mises from per-cycle rates) "barely separates sorts and favours default-like ones" and saturates with unit count (33.2 bits/s from 50 units vs 42.2 from 777) — [evaluation_spec.md](file:///C:/code/github/Kilosort/tuning/evaluation_spec.md) §12.
- **Exploratory explicit-purity measures.** `isolation.py` computes correctly assigned spikes Σ N(1 − ĉ) with Hill et al. 2011 contamination (τ_c 0.25 ms, τ_r 1.5 ms; 'plain' and 'local' co-modulation-aware variants). `tradeoff.py` plots correctly assigned against misassigned spikes as units are admitted cleanest first, cross-validated over halves. `make_variants.py` compares S of cut sorts with a matched random-deletion control. `uniqueness/` counts strongly tuned units without a nearby tuning twin. `amplitude.py` plots contamination against amplitude — [exploratory/README.md](file:///C:/code/github/Kilosort/tuning/exploratory/README.md). The set_cutoff port on KS4 gave +6–13% S over the matched random control, mostly explained by "low-amplitude spikes carry less heading information, which any score cut captures" — [placement_audit.md](file:///C:/code/github/Kilosort/tuning/exploratory/autocurate/placement_audit.md) §2.4.
- **Constraint.** "No hybrid data in later analyses (from 2026-11-03)": new sorts are scored without hybrid truth; the hybrid excerpt remains only in earlier results — [README.md](file:///C:/code/github/Kilosort/tuning/README.md).

### Inferences: where a principled objective could plug in
- **Cost-weighted spike errors (needs hybrid or simulated truth).** `hybrid.py` already computes per-unit matched / n_true / n_sorted. Replacing the agreement score with J = Σ_units (TP − c_FP·FP − c_FN·FN), with c set by the downstream analysis (e.g. how much an FP spike biases a tuning curve relative to the information an FN spike would have added), would generalise the KS4 paper's 1 − FP − FN, which is the special case c_FP = c_FN = 1. Natural home: a reported quantity beside guard §7.3, computed on the frozen hybrid excerpt. It cannot be the main objective now that new analyses use no hybrid data.
- **Yield above an FP/FN bar (KS4-paper style, truth-free version).** Count eligible units (or Σ spikes) whose held-out Hill contamination ĉ ≤ x% and whose spike count or presence clears a floor. `isolation.py`'s Σ N(1−ĉ) and the cross-validated `tradeoff.py` curve already give a precision–yield curve. The principled summary is "correctly assigned spikes at a fixed misassigned fraction" (an operating point on that curve), compared across sorts like ΔS. This fits as a selection-time check alongside §9.2, or as a second objective reported with S.
- **Decoy-estimated false-positive rate.** Refractory-period violations are a built-in decoy: spikes inside τ_r of each other cannot both be one neuron's. ĉ is a target–decoy-style FDR estimate per unit, and the jittered-copy nulls (§6.2, §6.3) and matched random-deletion controls are already decoy constructions. A harness extension could, for each threshold setting, estimate FDR(score bin) from refractory violations among spikes in that `Th_learned` score bin, using the per-spike scores that `ks4_sort_scored.py` saves. One would then choose the threshold, or a per-unit cut, at a target FDR. This is the truth-free counterpart of set_cutoff, with held-out estimation to avoid the 2× in-sample optimism the audit found.
- **Information.** S already is an information yield, and it behaves like a sensitivity-favouring objective. The FP spikes it penalises are those that degrade tuning; FP spikes in untuned or similarly tuned cells cost about nothing (§8.6, §12). To make S more principled about purity, add an explicit term: S − κ·(estimated FP spikes), with κ from the perturbation audit's −55.7 bits/s per 5% contamination. Alternatively, require ΔS to hold under a contamination-corrected re-scoring, analogous to the existing strict-duplicate check.
- **Placement in the pipeline.** Because `Th_learned`'s extra spikes cannot be undone inside stock KS4, any FDR-type objective that changes outputs (not only scores them) has to act after matching: either as a score cut or label (core vs tail), or through refractory evidence inside the final split/merge decisions, as the placement audit recommends.

### Gaps
- No harness run has yet scored sorts on an explicit FP/FN or FDR criterion; the exploratory measures are "not in a results document yet" ([exploratory/README.md](file:///C:/code/github/Kilosort/tuning/exploratory/README.md)), so how such an objective would rank H8, default and KS2.5 is unknown.
- How to choose c_FP/c_FN or κ for the user's downstream analyses (single-cell tuning versus population decoding) is not settled by any source found here.
